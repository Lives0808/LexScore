三个都在你提的清单上，一次做完。

### 一、三层 Agent 协同

把「一个 Prompt 解决所有问题」拆成**职责隔离的流水线**：

| Agent | 职责 | 不做的事 |
| --- | --- | --- |
| 1 · 语言层 | 语法纠错、搭配、语域、句式测量 | **不评分** |
| 2 · 语篇层 | 逻辑连贯、扣题度、论证结构 | **不纠语法** |
| 3 · 评分层 | 对齐官方 Rubric 打分 | **不看原文** |

关键约束是第三条：**评分层拿不到原文，只能看到前两层给出的结构化结论。**
这避免了「看到一个语法错误就顺手压低逻辑分」这类串扰 ——
规则引擎和 LLM 都适用同一条约束。

报告页新增「三层 Agent 协同」区块，把每一步的结论摊开展示。例如：

```
1 语言层   只做语言测量与纠错，不参与评分判断。
   语法错误句 4 / 16 · 学术词密度 1.2/100 词 · 句长标准差 10 · 复合句占比 50%
2 语篇层   只做逻辑、连贯与扣题分析，不纠语法。
   衔接手段 6/7 类 · 段落开头机械化 100% · 论证深度 0.9/100 词
   填充式废话 3 处 · 机械结构 1 处
3 评分层   只消费前两层的结构化结论，对齐官方 Rubric 打分 —— 不接触原文。
   TR 质量指数 47/100 · CC 59/100 · LR 46/100 · GRA 63/100
```

### 二、跨篇错误追踪

不再只是「存历史记录」。现在会跨篇分析，直接告诉你该专项突破什么：

```
最近 2 篇里，「because 与 so 不可连用」出现了 2 次
（累计 2 次，分布在 2 篇中）。这是当前最值得专项突破的一项。
```

每个错误类型会给出：
- **趋势判断** —— 变严重 / 在改善 / 新出现 / 持续存在
- **累计与分布** —— 共几次、分布在几篇里、最近几次
- **原文例子**
- **针对性建议**（来自规则库的解释，不是泛泛而谈）

还会分别列出「已改善」「已掌握」（以前错、最近不再错）与
「你自己用过的高分表达」。看到「已掌握」对坚持练习很重要。

实现上不依赖向量库 —— 错误类型本身就是结构化标签，直接聚合即可。
分析逻辑留在 TypeScript 引擎里（`LexScore.analyzeHistory`），
**安卓端通过引擎调用，不在 Kotlin 侧重写一份**，避免两端结论不一致。

### 三、模板检测细分

你提的关键区分：不能把「结构标记」和「填充废话」一视同仁。

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| **填充式废话** `filler` | `With the rapid development of society`、`Every coin has two sides`、`In a word` | 不承载任何信息，删掉不会损失内容 → **明确扣分** |
| **机械结构** `structural` | `Firstly / Secondly`、`In conclusion`、`Last but not least` | 本身是有效标记，只是用多了显套路 → **轻微扣分 + 建议变化表达** |

扣分权重也分开了：填充废话每处 0.07（上限 0.14），机械结构每处 0.02（上限 0.06）。

结论措辞也改了 —— 以前笼统说「检测到模板痕迹」，
现在会说「这几处是填充式废话，删掉只会让论证更紧凑」
或「这几处是有效结构标记，变化表达即可」。

**为什么这个区分重要**：混为一谈会让用户误以为「用 In conclusion 也会被扣分」，
从而写出更差的文章。
