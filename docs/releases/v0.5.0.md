## LexScore v0.5.0 — Kotlin + Jetpack Compose 原生安卓应用

之前两个版本的安卓 App 是 **Capacitor WebView 套壳**。这一版是**真原生界面**：
100% Jetpack Compose，Material 3，跟随系统深色模式，无任何网页界面。

### 下载

附件 `LexScore-Native-0.5.0.apk`（8.2 MB），传到手机安装即可。
首次安装需允许「安装未知来源应用」。

| | |
| --- | --- |
| 包名 | `com.lexscore.nativeapp` |
| 版本 | versionCode 6 · versionName 0.5.0 |
| 兼容性 | Android 8.0 及以上（minSdk 26） |
| 签名 | 与套壳版同一把密钥，两个 App 可并存安装 |
| 权限 | **无**（不需要网络、存储等任何权限） |

### 原生界面做了什么

- **首页**：任务类型选择（雅思大作文 / 小作文 / 托福综合 / 学术讨论）、
  题目、图表数据、阅读与听力论点、作文输入与实时字数、一键加载示例、历史记录
- **报告页**：总分卡、**用 Compose Canvas 手绘的四维雷达图**（含 Band 6.0 参考虚线）、
  四维评分卡（可展开评分依据与原文引用）、逐句对照批改
  （原文高亮 + 修改版预览 + 批注卡片，可单条接受 / 忽略）、
  扣题度 / 反模板 / 覆盖检测 / 硬性约束
- **语料库页**：统计概览、错误在评分项上的分布、好词 / 好句 / 高频错误分类

### 引擎怎么复用的（关键取舍）

**不把引擎重写成 Kotlin**，而是编译成单文件 JS 打进 APK：

```
lib/engine/ 的 TypeScript
      ↓  npm run engine:bundle（esbuild）
android-native/app/src/main/assets/engine.js  (185 KB)
      ↓  不可见的 WebView（V8）执行
原生 Compose 界面渲染结果
```

界面完全是原生 Compose，**只有计算层用 JS**。这样引擎源码只有一份，
安卓端与网页端结果逐字节一致，不存在「两端算法不一致」的维护陷阱。

> 一开始用的是更轻量的 `app.cash.quickjs`（纯 JNI，不依赖 WebView），
> 但它的 JS 栈上限写死在库内部，跑完整套分析（分句 + 上千次正则匹配 + 事实推导）
> 会抛 `stack overflow`，加大线程栈无效。
> 换到 WebView 后一次通过 —— 网页版每天都在跑同一份代码。
>
> **代价**：多一个 WebView 实例（约 20–30MB 内存），且求值发生在主线程。
> 后续如果要彻底去掉这层，方向是把引擎按段移植成 Kotlin。

### 完全离线

引擎跑在 App 内部，**飞行模式下也能批改**。作文与语料存在应用私有目录，
不联网、不上传、不需要账号。

### 验证

在 Android 15 模拟器上实测了签名的 release 包：安装 → 加载示例 →
批改 → 报告页（Band 6.5，四维 6 / 7.5 / 5 / 6.5）→ 逐句批注（32 条）全部正常。

仓库里留了一个调试钩子方便自动化验证：

```bash
adb shell am start -n com.lexscore.nativeapp/.MainActivity --ez lexscore_autorun true
```

会用第一篇示例自动跑一遍完整批改。

### 构建

```bash
npm run android-native:apk     # release（需要 JDK 17+ 与 Android SDK）
npm run android-native:debug   # debug
```
